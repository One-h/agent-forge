# 常见问题

## 设置页显示工作区不存在

检查设置页“基础配置”的工作区是否为绝对路径，且目录中包含需要给 Codex 使用的规则、技能和本地仓库。修改后立即生效。

## Gitea 自检失败

确认设置页保存的 Gitea 地址可从本机访问。重新在设置页保存 token。自检只验证当前用户读取权限，仓库本身仍需要在仓库选择中启用。

## 没有发现本地仓库

发现器只扫描工作区根目录及其 `runtimes/` 目录的第一层 Git 仓库，并要求仓库存在 `origin` remote。配置 Gitea 地址后，只展示同一 Gitea 主机的仓库。

## 飞书监听器没有运行

在终端执行 `lark-cli --version`，确认已安装并完成登录；再在设置页打开“监听飞书消息”。查看环境自检和服务日志获取错误详情。

## 飞书收到消息但 Codex 没有开始回复

在终端执行 `codex app-server --help`，确认当前 Codex CLI 提供 app-server。设置页中的 Codex 通道默认显示“按需启动”，第一条需要回复的飞书消息到达后才会变为运行中。同一飞书会话已有活动任务时，新消息会追加到当前 turn，不会再启动并发的 `codex exec resume`。

## Codex 任务无法执行

确认 `codex --version` 可用、工作区路径正确且用户对对应仓库拥有本地读写权限。自动 Issue 修复还需要在设置页开启“允许 Issue 修复”。

## 常驻服务没有启动

在设置页确认常驻服务已安装。日志位于项目的 `data/launchd/`；若开发服务器仍占用 4731、4732 或 4734 端口，先停止开发服务，再点击“重启”。

## 磁盘占用持续增长

在设置页“本地数据”选择保留天数后清理已结束任务产物。正在运行的任务、SQLite 数据库、钥匙串凭据不会被该清理操作删除。

## 无法从其他设备访问

这是默认行为。服务仅绑定 `127.0.0.1`，避免本机 token、任务数据和 Codex 控制入口暴露到局域网。
